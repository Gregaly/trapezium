# Changelog

Every `@trapezium/*` package is released together at the same version, so this one file covers all of them. Each entry says what changed for someone using the library, which adapters it reaches, and anything that behaves differently from before. The per-package `CHANGELOG.md` files, written by Changesets, carry the same releases in their own words.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow [semver](https://semver.org/). Before 1.0 a minor version can add to the API but never removes or renames anything without saying so here, with a migration note.

## Unreleased

### Added

- **Header controls.** `renderHeaderControls(context)` on a column puts controls of your own in its header — a search box for the column, a filter button, a toggle — where `renderHeader` can only put text. They are drawn after the sort control and before the column's menu, outside the sort control, so they can be links, buttons and inputs, and they take the header's spare width while the text keeps to its own. A click, a key or a press in them never sorts the column or picks it up to move it: pressing in one turns the header's dragging off until the press ends, so text typed in a box can be selected. Called again as the state changes, with the column's current `sort`; React and Vue keep the controls in place, so an input keeps its focus and text while it changes the table, and in plain JavaScript and Svelte returning the same node does the same. Rendered on the server in every adapter; in Vue it may return a VNode. Hidden with the header row in the card layout. The header carries `data-controls="true"` and the slot is `.tpz-th-controls`. See [docs/rendering.md](docs/rendering.md#controls-in-a-header).

## 0.4.0 — 2026-10-15

### Added

- **Detail rows** (master/detail). `detail={{ render }}` opens content below a row, spanning the table, from an expander column that leads it — a chevron per row and one in the header for every row on the page. Any number open at once. Open rows are `state.expanded` (row ids), so they are controllable, saved with a view, and carried in the URL with `include: ["expanded"]` (`open=id1,id2`); the server renders open rows open. `canExpand(row)` leaves rows without one, `keepMounted` keeps a closed detail alive so it does not fetch again, and `toggleOnRowClick` opens it from anywhere on the row. A detail row is never counted, paged, sorted, selected or exported, takes its content's height with nothing measured, and works with append pagination, density, `responsive="cards"` and server mode. Every adapter; in Vue `render` may return a VNode. See [docs/rows.md](docs/rows.md#detail-rows).
- Core: `toggleExpanded`, `setExpanded`, `collapseAll`, `isExpanded`, `expandableIds`, `isDetailOpen`, `isInteractiveTarget` and `INTERACTIVE_SELECTOR`; the `DetailOptions` and `DetailContext` types; `expanded` in `URL_KEYS`.
- **Inline cell editing.** `editable: true` (or a function of the row) on a column, and `onCellEdit` on the table. A cell opens on double-click (`editTrigger: "click"` for a single click), Enter, F2 or typing a character, which seeds the editor; Enter, Tab and leaving the cell commit, Tab moves to the next editable cell, and Escape cancels without reaching anything around the table. Editors by type: text, number with the column's precision (an amount in minor units is edited in major units), a filterable ARIA combobox for any column with `formatOptions.options` and for yes/no, and the browser's date, date-time (in the table's time zone) and time pickers. `renderEditor(context)` supplies your own, with `commit(value)` and `cancel()`. Per column `parse` and `validate`: a refused value is not committed, and the editor is marked invalid with the reason beside it. The table never changes `data` — it reports `{ rowId, row, key, value, previousValue }`, values in the shape they replace — and a returned promise shows the cell as saving, then as failed if it rejects. Popups stay inside the window, flipping above near the bottom. No editor is ever open in a server render. Every adapter; in Vue `onCellEdit` is a prop (`@cell-edit`) so it can return a promise, and `renderEditor` may return a VNode. See [docs/editing.md](docs/editing.md).
- **Keyboard cell navigation.** `cellNavigation` (on automatically when a column is editable) makes the table a `role="grid"` with one tab stop: the arrows, Home, End, Control+Home/End and Page Up/Down move between cells, Enter goes into a cell's link or button and Escape comes back, and Space works the checkbox and the expander from their cells. A visible focus ring, `--tpz-focus-ring`.
- **The active cell is state** — `state.focus: { rowId, key?, align? } | null` — so moving to a row is declarative. Setting it from outside (`focusCell(state, rowId, key, align)`) brings the row onto its page in client mode, scrolls it into view, highlights it (`data-focused`, `--tpz-focused`) and, with cell navigation on, focuses the cell. The server renders the right page with the highlight on. Carried in the URL as `at=rowId:key` when `include` names `"focus"`.
- **Child rows, one level.** `getParentId(row)` draws each row whose parent is in the data directly under it, indented, with a toggle on the parent that folds its children away (`state.collapsed`, opt-in to the URL as `fold=`). Sorting orders parents and children among themselves; filtering and search test each row, showing a parent as context when only a child matches and a matching parent alone when none of its children do; paging and totals count parents, so a family is never split across pages. Children are selected, edited and exported like any row, exported under their parent. `rowClassName` gets the row's place as a third argument. With cell navigation the table is a `treegrid`. Every adapter. See [docs/rows.md](docs/rows.md#child-rows). Not grouping, not aggregation, not multi-level trees: deeper rows go under the top of their chain.
- **Pinned rows.** `pinnedRows={{ top, bottom }}` holds rows outside the data at the top and bottom of the table — an editable "new entry" row, a totals row — drawn through the same columns, renderers and editors, in bodies of their own that stay in view while the body scrolls. Never filtered, sorted, paged, counted, selected or exported. Edits of them carry `pinned`, and with cell navigation the up arrow from the first data row reaches them. Every adapter. See [docs/rows.md](docs/rows.md#pinned-rows).
- **Row reorder by drag.** `rowReorder={{ onReorder, canDrag? }}` leads each row with a drag handle. A drag shows where the row will land and scrolls the table, or the page, near the edges; Alt with an arrow key moves a row from the keyboard, with the move announced. `onReorder` gets `{ rowId, row, afterId, beforeId, parentId? }` — neighbours counted among every matching row, not only the page — and a returned promise shows the new order until it settles. Only offered while the table is unsorted. Child rows move among their siblings; a parent takes its children. On touch screens a long press picks the row up, and scrolling is never blocked. Every adapter. See [docs/rows.md](docs/rows.md#moving-rows).
- **Selection additions.** `selection={{ selectAll: "matching" }}` makes the header checkbox select every row the filters and search leave, on every page — in server mode by asking `server.all`. `selection={{ dragSelect: true }}` selects the rows a press sweeps across, with a threshold so a click stays a click, auto-scroll at the edges, and Shift to extend; it ignores controls in the row and the drag handle. In every table with selection, Shift with an arrow key extends a range from a row's checkbox (or any cell, with cell navigation), and Escape clears the selection — never an Escape an editor or menu has used. Every adapter. See [docs/selection.md](docs/selection.md).
- **Faster at 100,000 rows.** Each stage of the pipeline is remembered until something it reads changes, so turning a page, selecting, moving the active cell or opening a detail no longer re-runs filtering, searching and sorting — at 100,000 rows that was a tenth of a second or more each time, and is now nothing. Global search matches each row as one remembered string: a keystroke across 26 columns of 100,000 rows takes ~35 ms instead of ~270 ms. With a search box, that string is built in idle time after the first render, so the first keystroke is as quick as the rest. Formatting an amount in minor units is about twice as fast. Every adapter, nothing to configure. Numbers for sort, set filter and search at 100,000 rows, and a proposal for very long appended lists, in [docs/performance.md](docs/performance.md).
- **A context-menu hook.** `onRowContextMenu(row, event, info)` fires for a context menu on a row with the cell under the pointer: `{ rowId, columnKey, column, text, rowText, pinned? }`, where `text` is what that cell shows and `rowText` is the row as the table's own "Copy to clipboard" writes it — so "Copy cell" and "Copy row" items match the table exactly. `cellDisplayText(row, column, { types, format })` is exported for anything else that must say what a cell says. Every adapter; `@row-context-menu` in Vue. See the recipe in [docs/recipes.md](docs/recipes.md).
- **Column descriptions.** `description: "…"` on a column shows a tooltip beside the header while it is hovered or has the keyboard, linked with `aria-describedby` so a screen reader reads it too, with a dotted underline marking described headers. No renderer needed. Every adapter.
- **Column `grow`, and pinning by width.** `grow: 1` on a column gives it the width the table has to spare while every other column keeps to its content or its `width`; several growing columns split it in proportion. `pin: { side: "start", below: 640 }` freezes a column only while the table is narrower than 640px (or `above` a width), decided by a container query in a `<style>` the table writes into its own markup, so the server freezes the same columns as the browser. The column stays where it is in the order. Every adapter. See [docs/columns.md](docs/columns.md#width-alignment-and-wrapping).
- Core: `columnSizing`, `pinWhenToken`, `responsivePinStyles`; the `ResponsivePin` and `CellSizing` types; `pinWhen` on a resolved column.
- Core: `cellDisplayText`; the `RowContextMenuInfo` type. `toDelimitedText` and `exportCell` re-exported from every adapter.
- Core: `createPipelineCache` and `cache` in `getRows`; `warmSearch`, `warmSearchWhenIdle`, `WARM_SEARCH_FROM`; `foldText`. `bench/scale.mjs` and `bench/browser/append.html`.
- Core: `rangeSelection`, `startDragSelect`, `createEdgeScroller`; `selectAll` and `dragSelect` in `SelectionOptions`.
- Core: `moveRowTo`, `stepRow`, `applyRowMove`, `canReorderRows`, `startRowDrag`; the `RowMove` and `RowReorderOptions` types. The `dragCell` class slot.
- Core: `pinnedRowId`, `pinnedOffset`, the `PinnedRows` and `PinnedSide` types. The `--tpz-pinned-bg` variable.
- Core: `toggleCollapsed`, `setCollapsed`, `isCollapsed`, `parentIdsWithChildren`, `getRowsWithChildren`; `getParentId` in `getRows` and `info` in its result; the `RowInfo` type; `collapsed` in `URL_KEYS`.
- Core: `focusCell`, `clearFocus`, `nextCell`, `entryCell`, `isNavigationKey`, `isCellEditable`, `hasEditableColumns`, `editorKind`, `editorOptions`, `editorStep`, `toEditorText`, `fromEditorText`, `validateEdit`, `editValuesEqual`, `typedCharacter` and `placePopup`; the `CellFocus`, `CellEdit`, `EditorContext`, `EditorKind`, `NavigationGrid` and `NavigationKey` types; `reveal` in `getRows` and `page` in its result. Rows carry `data-row-id`.
- Class slots `expandCell`, `detailRow` and `detailCell`, and the `--tpz-detail-bg` variable.
- `id` in plain JavaScript, Svelte and Vue, as React already had: the base for the ids the table gives its own elements.

### Fixed

- **`renderHeader` is rendered.** It was in the column type from 0.1.1 but never drawn. It now replaces the header's text, with the icon, the sort control, the menu, header search and the resize handle still around it and working, and it is given the column's current sort. It sits inside the sort control, so it should return phrasing content; the control keeps the column's `header` as its accessible name. Every adapter, server render included; in Vue it may return a VNode.

- Hovering or selecting a row tinted its frozen cells with a translucent colour, letting scrolled content show through the frozen column. The tint is painted over an opaque background again. Every adapter.

### Changed

- **`width` is held exactly.** It was only a starting width: the table spread spare room across every column, so a 56px icon column could render 130–210px wide. Now the header and every cell take it as width, minimum and maximum, and content that does not fit ends in an ellipsis. `maxWidth` likewise caps the cells, where before it only reached the header. A column with `wrap` and a `width` now wraps at that width. If you relied on a `width` growing to fill the table, use `grow` or `maxWidth` instead. Every adapter.

- `onRowClick` now ignores a click on any control inside the row — a link, button, input, select, label, `[role="menu…"]`, or anything marked `data-tpz-interactive` — as the documentation already said it did. Before, only the table's own links and checkboxes were excluded, so a button rendered in a cell also fired the row's click. Every adapter.
- `TableState` has optional `expanded`, `collapsed` and `focus` keys. They are optional so that a state written before they existed still type-checks; every table fills them in as `[]`, `[]` and `null`.

## 0.3.0 — 2026-10-14

- A row of one line is exactly `--tpz-row-height` (28, 32 and 40px at compact, normal and relaxed) under `rowHeight: "fixed"` and `"auto"`, whatever the cells hold. Badges, tags and buttons in a cell are one line tall; the selection checkbox lines up with the first line of an auto-height row.
- `--tpz-cell-content-height`: the height available inside a cell, for renderers that fill it.
- A server-paged table no longer guesses `badge` from the rows on one page. `inferType` and `inferColumns` take `{ partial: true }`; `resolveColumns` takes `server`.
- Docs and `llms.txt`: a section on what a custom cell renderer should do to keep a row one line tall.

## 0.2.0 — 2026-10-11

- Multi-column sorting: shift-click a second header, levels numbered in the headers, "Then sort" in the column menu, and a reset control in the toolbar. `sortable={{ multiple, reset }}`.
- `headerSearch`: a magnifier in each header that turns it into a search box for that column, as a `contains` filter.
- The text operators (`contains`, `startsWith`, …) match what a cell shows, for every type.
- Plus fixes to boolean and time filters, header rebuilding in the DOM renderer, column resizing, `box-sizing`, and faster equality filters. New core helpers: `addSort`, `removeSort`, `resetSort`, `setColumnSearch`, `columnSearchText`, `resolveSorting`, `canResetSort`, `sortsEqual`, `sortPriority`, `resolveHeaderSearch`, `isTextOperator`, `createTextTest`.

## 0.1.1 — 2026-09-08

- A header that is a link no longer drags as a URL. "Download CSV" exports the selected rows when there are any.

## 0.1.0 — 2026-09-07

- First public release, with `rowHeight="auto"` and exact row heights, `wrap` as a line count, append pagination that renders only the new rows, and `--tpz-header-height`.
